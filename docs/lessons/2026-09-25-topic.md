# Bài học kinh nghiệm: Kiểm tra biến môi trường của tiến trình API

## Sự cố

Trong quá trình chuyển Add2Num thành REST API, ứng dụng được cấu hình để đọc API key từ biến môi trường `ADD2NUM_API_KEY`. Biến đã được tạo trong Windows nhưng request vẫn nhận phản hồi `401 Missing or invalid API key`.

## Nguyên nhân

Tiến trình Spring Boot và terminal đang chạy được khởi tạo trước khi biến môi trường mới được cập nhật. Việc kiểm tra trong một terminal mới hoặc trong phần Environment Variables không đảm bảo tiến trình API hiện tại đã nhận giá trị đó.

## Bài học rút ra

- Biến môi trường được truyền vào lúc tiến trình khởi động; thay đổi biến không tự động cập nhật ứng dụng đang chạy.
- Khi xử lý lỗi xác thực, cần phân biệt rõ: thiếu header, sai API key, hay ứng dụng chưa đọc được cấu hình.
- Không đưa API key thật vào source code, README, log hoặc file commit.

## Cách phòng tránh

1. Đặt biến môi trường trước khi khởi động API.
2. Mở terminal mới hoặc khởi động lại VS Code sau khi thay đổi biến cấp User/System.
3. Kiểm tra biến trong đúng terminal dùng để chạy Maven/Spring Boot.
4. Gửi thử request với API key hợp lệ và xác nhận request không có key vẫn bị từ chối.
5. Chỉ log trạng thái cấu hình như `API key configured`, không log giá trị key.

## Checklist xác minh

- [ ] `ADD2NUM_API_KEY` tồn tại trong process khởi động ứng dụng.
- [ ] Ứng dụng đã được restart sau khi đổi cấu hình.
- [ ] Request dùng đúng header `Authorization: Bearer <api-key>`.
- [ ] API trả `401` khi thiếu hoặc sai key.
- [ ] API trả kết quả thành công khi key hợp lệ.
